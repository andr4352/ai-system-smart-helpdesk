# Лабораторная работа 3

Реализация компонента маршрутизации обращений студентов

## 1 Выбор компонента

Тема проекта — умная маршрутизация обращений студентов. Цель работы — реализовать локальный компонент, который проверяет текст, определяет категорию и предлагает ответственный отдел. Неоднозначные обращения передаются оператору.

На схеме ЛР2 компонент занимает блоки «Pydantic», «Сервис маршрутизации» и «Общий Pipeline TF-IDF и модель». Вход поступает из вызывающей программы, в демонстрации — из app/demo.py. Веб-сервер и внешний AI API для запуска не нужны.

## 2 Репозиторий и окружение

Работа выполнена в ветке feature/lab3-component прежнего репозитория. Использован Python 3.12 и отдельное окружение .venv. Версии основных библиотек закреплены в requirements-component.txt. Команды из корня проекта:

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements-component.txt
python -m app.ml.training
python -m app.demo
python -m pytest tests/test_component.py -q
```

Обучение создаёт собственный небольшой артефакт artifacts/helpdesk.joblib и его описание helpdesk.json. В Git хранятся код и учебный CSV; окружение, веса, ключи и рабочая БД исключены через .gitignore.

## 3 Входной и выходной контракт

Метод Predictor.predict принимает PredictionRequest или словарь и возвращает PredictionResponse. Схемы вынесены в app/schemas.py и не зависят от FastAPI.

| Поле | Ограничение |
|---|---|
| item_id | Строка TKT- и от 1 до 10 цифр |
| text | Строка от 10 до 3000 символов после удаления крайних пробелов; лишние поля запрещены |
| request_id | UUID для связи запроса с результатом |
| prediction | ACCOUNT, STUDY, PAYMENT или OTHER |
| confidence | Оценка модели от 0 до 1 |
| route | IT, DEAN_OFFICE, FINANCE или OPERATOR |
| model_version | Непустая строка версии модели |
| manual_review_required | true — нужна проверка оператором |

В ответе сохраняется item_id. Неверный вход вызывает ValidationError. Если артефакт отсутствует, повреждён или не загружается, возникает ModelUnavailableError с кодом MODEL_NOT_READY. Сбой инференса или неверный вывод модели дают MODEL_INFERENCE_FAILED. Успешный результат при отказе не возвращается.

## 4 Подготовка данных и модель

Использован учебный набор из 64 вымышленных обращений, по 16 на каждую категорию. Файл data/demo_train.csv содержит item_id, text, label. Тестовые фразы заданы отдельно в tests/test_component.py и app/demo.py. Реальных персональных сведений нет.

app/ml/preprocessing.py переводит текст в нижний регистр, заменяет «ё» на «е» и убирает повторные пробелы. TF-IDF преобразует слова и пары соседних слов в числовые признаки. Логистическая регрессия выбирает категорию; параметры: C = 10, max_iter = 1000, random_state = 42.

Обучение находится в app/ml/training.py, загрузка и прогноз — в app/ml/inference.py. Нормализация, словарь TF-IDF и классификатор сохраняются в одном Pipeline. На новом обращении вызывается только predict_proba, без повторного обучения. confidence — максимальная оценка класса, а не подтверждённая вероятность правильности.

Версия модели — helpdesk-tfidf-lr-1.0.0. Манифест хранит версии библиотек, число примеров, классы и SHA-256 данных и модели. Перед загрузкой проверяются версия scikit-learn и контрольная сумма. Загружается только собственный joblib: совпадение SHA-256 само по себе не делает чужой файл безопасным.

## 5 Прикладное правило

В app/services/prediction.py модельный вывод отделён от маршрутизации:

```python
manual = confidence < 0.8 or category == "OTHER"
route = "OPERATOR" if manual else ROUTES[category]
```

Справочник: ACCOUNT → IT, STUDY → DEAN_OFFICE, PAYMENT → FINANCE. OTHER всегда передаётся оператору. Ровно 0,8 допускает автоматический маршрут для трёх основных категорий. Компонент возвращает рекомендацию; сам ничего не отправляет в подразделения.

## 6 Тестирование

Тесты выполняются локально без сети. Настоящая модель обучается во временном каталоге. Для проверки сбоя зависимости используется отдельная подмена, вызывающая ошибку.

| Проверка | Ожидаемое и полученное поведение |
|---|---|
| Вход в кабинет и оплата | Разные категории и отделы; ответ соответствует схеме |
| Вопрос о пересдаче | STUDY, но confidence < 0,8: оператор |
| Неясный текст | Низкая уверенность и ручная проверка |
| Ошибки ввода — 7 случаев | Пустой текст, пробелы, 9/3001 символ, число вместо текста, неверный ID, лишнее поле: ValidationError |
| Границы 10 и 3000 | Оба значения принимаются |
| Нет или повреждён артефакт | ModelUnavailableError; ложного успеха нет |
| Нечитаемый файл и сбой модели | Загрузка отклонена либо MODEL_INFERENCE_FAILED |
| Неверный вывод — 3 случая | Неизвестный класс, NaN и confidence > 1 отклоняются |
| Одинаковая нормализация | Регистр, «ё» и пробелы не меняют прогноз |
| Порог и OTHER — 3 случая | 0,7999: оператор; 0,8: IT; OTHER: оператор |

Результат: 24 passed in 2.28s. Полный набор с тестами ЛР2: 28 passed, 1 warning in 1.88s. Предупреждение относится к устаревающему способу подключения httpx в Starlette; ошибок тестирования нет. Полные журналы сохранены в docs/lab3_component_tests.txt и docs/lab3_all_tests.txt.

## 9 Ответы на контрольные вопросы

1. Входной контракт и модель. Контракт задаёт поля и ограничения; модель учится находить категорию по тексту.

2. Независимость от fastapi.Request. Компонент должен работать из обычной программы и тестов без сервера.

3. Отделение бизнес-правила. Модель определяет класс, а справочник и порог задают действие. Их можно менять отдельно.

4. Расхождение предобработки. Если текст обрабатывается по-разному при обучении и запуске, признаки меняются. Общий Pipeline предотвращает это.

5. Тестирование платного API. Вызов подменяют заранее заданным ответом или ошибкой; реальные запросы не нужны.

6. Нет или повреждён артефакт. Выдать явную ошибку, не возвращать выдуманный прогноз; восстановить собственную модель.

7. Произвольное число и вероятность. Число становится обоснованной оценкой только при подходящем методе и проверке. Здесь predict_proba не калиброван на реальных данных.

8. Передача человеку. При confidence < 0,8 или OTHER ставятся route = OPERATOR и manual_review_required = true.

9. Опасность pickle и joblib. При загрузке они могут выполнить код. Поэтому чужие артефакты не используются.

10. Изменения схемы ЛР2. Сохранены её основные блоки; добавлен самостоятельный Predictor и общий модуль схем вместо привязки к API.
